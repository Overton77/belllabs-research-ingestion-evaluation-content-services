# Agent-capability seed notes (FT-A6)

Seed bundles `mc.catalog.agent-capabilities@1.0.0` (common), `mc.app.biotech.agent-capabilities@1.0.0`
and `mc.app.ai-engineer.agent-capabilities@1.0.0` are generated by `generate_catalog_seeds.py` from
`agent_capabilities.py` and `tests/fixtures/mcp/<id>.tools.json`. They require migration 0025.

## Tool lists

The `tools/list` fixtures are transcribed from `docs/specs/fast-track-2026-10/research/seed-capabilities-and-formats.md`
(`capture_method: transcribed`); no server was run in this wave. Input schemas are recorded as
`{"type": "object"}` until a live capture. Re-capture each server once with
`scripts/capture_mcp_tool_snapshot.py`, replace the fixture, regenerate the bundles (new seed
version if 1.0.0 was applied) and run `make seeds-validate`.

# Agent-skill seed notes (FT-A7)

Seed bundles `mc.app.biotech.agent-skills@1.0.0` and `mc.app.ai-engineer.agent-skills@1.0.0`
are generated by `generate_catalog_seeds.py` from `agent_skills.py`. There is no common
agent-skills bundle: an `mc.capability_bundle_manifest.v1` names its application, so the same
bytes have one manifest digest and one object prefix
(`<application>/<kind>/<id>/<version>/<manifest sha256>`) per application. Each bundle depends on
`mc.catalog.agent-capabilities` and its application's `agent-capabilities` (plugin members), and
requires migration 0025.

| Capability | Applications | Source (bytes never edited) |
| --- | --- | --- |
| `skill.agent-browser` 0.38.2 | both | `vercel-labs/agent-browser` `skills/agent-browser` at `39a74c70d7759d5a6de7a22c04570bb626bbd081` (tag `v0.38.2`), the stub that runs `agent-browser skills get core` |
| `skill.biomcp` 0.9.1 | biotech | `biomcp skill install` of `biomcp-cli` 0.9.1, captured on Linux (the installer refuses Windows: "Atomic skill installation is unsupported on this platform"); `.biomcp-skill.json` carries the capture's `installed_at` |
| `skill.edgartools` 5.61.1 | ai-engineer | `edgar.ai.install_skill(use_symlinks=False)` of `edgartools` 5.61.1, captured on Linux (every file equals the `edgar/ai/skills` blob at `7338aa335f6442c52dfa0695422cf1cd27e946e0`; the Windows copy mode writes `SKILL.md` with CRLF, so it is not the canonical capture) |
| `skill.mission-control` + five `skill.mission-control-*` | both | `skills/` (LF bytes; per-file digests equal `make skills-manifest`) |
| `hook.mc-policy-template` 1.0.0 | both | `scripts/hooks/policy_template` (events `before_shell`, `before_tool`; `fail_closed`) |
| `plugin.web-research` | both | members `mcp.tavily`, `mcp.firecrawl`, `skill.agent-browser`, optional `mcp.agent-browser` as exact pins; `capability_plugin_member` rows; host support is the intersection |

Captures live under `tests/fixtures/skills/` with `-text` git attributes (no line-ending
conversion) and are excluded from the whitespace hooks.

- **Conflict to resolve with the owner:** upstream edgartools 5.61.1 `SKILL.md` declares
  `name: EdgarTools`, which breaks the Agent Skills name rule (lowercase, equals the directory).
  The bundle stays verbatim (Mission Control adds nothing inside a third-party bundle) and the
  catalog's `skill_name` is the directory name `edgartools`. Hosts that validate the frontmatter
  name strictly may reject it.
- Bytes reach the bucket only through `scripts/seeds_publish_bundles.py --target <app> --storage
  supabase` (publisher credential, never the service key); nothing was uploaded to a live bucket.
- `skill.mission-control-coordinator` (frozen `mc.catalog.approved-assets@1.0.0`) is not retired
  here: the coordinator catalog bindings still resolve it; retire it in a later seed version
  together with the consumer change.
