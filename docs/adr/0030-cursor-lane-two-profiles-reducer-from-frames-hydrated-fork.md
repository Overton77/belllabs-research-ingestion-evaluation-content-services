# Cursor is the second lane family: cursor_local runs the Python SDK bridge in the worker with a leased workspace, cursor_cloud drives the Cloud Agents API; both derive state from frames, inject context through workspace files, and emulate fork and continuation by hydrating a fresh agent from a Context Packet

The Cursor Python SDK (1.0.37) offers no steer, fork, pause or system prompt, but it offers stable `agent_id`, `run_id` and `call_id`, a resumable local event offset and a resumable cloud SSE stream (`Last-Event-ID` within the published retention window), file-based hooks, workspace-loaded rules, skills and subagents (`.cursor/agents/*.md`, also accepted inline through `AgentOptions.agents` and as cloud `customSubagents`), and a terminal result with usage and `git.branches[]`. The lane therefore (1) materializes everything it wants the agent to know as files: `.mission/` with the Context Packet, `AGENTS.md` and an `alwaysApply` rule in `.cursor/rules/` for instructions, `.cursor/skills`, `.cursor/agents`, `.cursor/mcp.json` and `.cursor/hooks.json` from host projections; (2) observes `run.observe(after_offset)` locally and the SSE stream in the cloud, persisting every frame (ADR-0028); (3) declares its control matrix honestly in `describe`; (4) treats each `send` as a Session Turn and each agent as an Agent Session; (5) implements continuation and fork by creating a new agent in a fresh workspace hydrated from the packet and the previous workspace's git patch (local) or branch (cloud); (6) runs Mission Control's kernel hooks as command hooks that call the worker over loopback (`fail_closed` on the permission events `preToolUse`, `beforeShellExecution`, `beforeMCPExecution` and `beforeReadFile`; observation hooks fail open so a hook outage cannot stall the agent) with a task-scoped token so the stop fence and Operation Intent apply before shell and MCP side effects, which matters because headless local runs auto-approve every tool call; (7) creates cloud agents with a client-supplied `agentId` so a lost response is recovered by `409 agent_id_conflict` rather than a duplicate paid agent. `cursor_local` is qualified first (ADR-0019) because it needs no new accounts and keeps the workspace on the worker; `cursor_cloud` follows with the same contracts and a repository-based workspace.

## Consequences

- `execution_runtime` gains `cursor`; a `CursorExecutionBinding` pins SDK and bridge versions, model, mode, workspace, projections and the hook callback endpoint.
- Usage is `estimated` until `get_usage` settles; the reducer records both.
- Cloud `409 agent_busy` maps to `wait_then_send`, never to a retry with a new run; cloud `sessionStart` hooks do not fire, so the packet index must be complete on disk before the first send.
