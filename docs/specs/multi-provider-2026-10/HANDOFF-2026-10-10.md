### Integration decisions

- **Describe convention.** `application/execution/harness/describe.py` is the single source;
  adapter `describe.py` modules re-export. An implemented cell states `native` or `emulated` with
  `qualified=False`; `unqualified` only where nothing is implemented. Partition:
  `V1_LANE_PROFILES={deep_agents}`, `V2_IMPLEMENTED_LANE_PROFILES={cursor_local, cursor_cloud,
  claude_agent_sdk, codex}`, `V2_STUB_LANE_PROFILES={claude_cloud, codex_cloud}`. Codex resume is
  `wait_then_send`.
- **Release 1.2.0.** The locks pin 1.1.0 = 0001-0030, and the repository had appended 0031/0032
  under the same version. The repository component became 1.2.0 = 0001-0033 with the locked 1.1.0
  as declared predecessor. `0033_approvals_coordinator_inbox_lane_describes.sql` = MP-11
  `approval_correlation`/`governed_effect_intent`, MP-15 inbox/notification/causation, and a
  generated `lane_profile` describe refresh for the four implemented profiles
  (`scripts/lane_describe_refresh.py`). Fingerprint `sha256:0113df03…`; a real 1.1.0 → 1.2.0 upgrade
  was proven as a non-superuser migrator on disposable clusters. Locks untouched. MP-12's typed
  phase columns are deferred. Next free migration 0034; next free ADR 0042.
- **Session Lane routing.** Production families would have sent Claude and Codex units down the
  governed `operation.execute` path. Now `SESSION_LANE_RUNTIMES = {cursor, claude, codex}`
  (`domain/execution/contracts.py`) are always segment-driven with bounds from their own
  `provider_binding.budgets` and run `lane.*` on `provider_binding.task_queue`.
- **Capacity policy.** Additive `OperationWorkflowRequest.capacity_wait` carries the
  `MISSION_CONTROL_CAPACITY_*` settings into both family request builders and `plan_limit_response`;
  absent in old histories, which replay to the defaults.
- **Attempt recording.** `admit_lane_session(attempt=)` records the attempt row through
  `lineage.observe_attempt`; previously only the governed path did, so Session Lane frames had no
  attempt row (a production gap for Cursor too).
- **Output custody.** A Session Lane's final JSON object is its Completion Candidate (full text up
  to 262,144 characters through `FinalTextLane.final_text`), and declared `outputs/` files become
  digest-checked `workspace-candidate://` refs (`WorkspaceCandidateLaneOutputs`, all four Session
  Lane compositions).
- **Lane queues.** Production polled only `<base>.agent-cognitive`; bindings routed to dedicated
  lane queues were never served. `MISSION_CONTROL_LANE_TASK_QUEUES` now adds lane workers
  (`ProductionWorkerSet.lanes`).
- **Usage charging.** A Session Lane settlement charges its closing token usage once to the run's
  reserved or declared token dimensions; unknown charges nothing; no subagent double count.
- **Provider lanes.** `adapters/temporal/provider_lane_composition.py`: one approval broker per
  worker (connection = session owner ref), `compose_claude_local_lane` and
  `compose_codex_local_lane` (opt-in `MISSION_CONTROL_CLAUDE_LANE` / `MISSION_CONTROL_CODEX_LANE`,
  non-Windows, MP-05 auth admission, credential-free child environment, Kernel Hooks, leases,
  broker permissions), approval reviewers default `owner`, approval waits capped at 600 s.
- **Continuation.** `adapters/temporal/continuation_composition.py` composes the MP-12 phase
  service, hydrator registry (Cursor local/cloud, Claude, Codex), pressure coordinator and mailbox
  hold oracle; `continuation.*` served on the cognitive queue; `ContinuationInFlight` → typed
  retryable `continuation_in_flight`. Recorded as [ADR-0041](../../adr/0041-continuation-is-a-persisted-phase-machine-driven-by-the-operation-workflow.md) (`proposed`).
- **Human control.** Production manifest lowering of `human_gate` nodes and Goal Loop review; a
  denied manifest Human Gate fails the run (`mp20-stagegraph-concluded-failure`), a linked child
  that concluded failed is recorded `failed` (`mp20-linked-child-concluded-failed`), a gate stage's
  legacy wait is pre-satisfied (`satisfied_wait_ids`). MP-11 approval tasks share the
  `HumanTaskService`; `POST /human-tasks/{id}/approval-resolutions`; governed MCP tools; an accepted
  cancel closes the run's open approval tasks.
- **Authoring.** mission/v2 compile, V01 admission and `mc.manifest_launch_bindings.v2` with a
  `providers` section (sealed `ProviderExecutionBinding`); `cursor_launch.py` seals
  `mc.cursor_binding.v1` from v1 and v2; `ProviderBindingRows` so provider lanes render their
  capabilities; `packet_binding_name` fixed every manifest Stage Graph dependency slot (all lanes);
  authored `inputs[].name/expand` carried as `StageAuthoredInput`;
  `merge_environment_documents` replaces an environment of another kind (was a 500).
- **Cursor.** `GitBranchPublisher.publish` commits a later unit's packet on top of the run branch
  head; projection writes unlink first; `packet_files` maps role and mount roots to the lease root.
- **Realtime and inbox.** SPEC-04 lineage, descendants, watchdog, receipt following, chain targets,
  per-execution cursors and `CURSOR_EXPIRED`; the API composes `CoordinatorInboxService` and the
  HTTP inbox only where release 1.2.0's `coordinator_inbox` exists.
- **Declined:** `_binding_digest` → `provider_binding.binding_digest` (would change the policy
  digest both lanes proved equal to the approval probe's); extending `_RECORDED_DETAILS` with typed
  columns (details stay in describe and frames).
