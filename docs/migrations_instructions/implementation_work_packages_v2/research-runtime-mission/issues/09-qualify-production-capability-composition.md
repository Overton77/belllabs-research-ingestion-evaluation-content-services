Provide the deployment-supplied worker activity composition rather than relying on test injection. Resolve exact skills/tools/CLI/MCP/checkpointer/storage/workspace dependencies and qualify their actual availability. The uncommitted component harness may only be used after a reviewed ownership/dependency commit; aiengineer integration is optional, not an invented prerequisite.

- [ ] Real application PostgreSQL, Mongo immutable definitions/bindings, object artifact storage and persistent LangGraph saver/store are composed through existing ports. *(Partly proven: PostgreSQL, Mongo, the persistent saver/store and the content-addressed filesystem payload store are composed and qualified; the S3 object store is composed when `S3_BUCKET` is set but was not qualified.)*
- [x] Root/family/operation workers and queues use the canonical registries and exact placement; no parallel demo runtime.
- [x] Search and browser skill bundles/tools are digest/revision pinned, mounted/disclosed and actually invoked by the bounded runtime agent.
- [x] Research outbound access is provided by a qualified mediated service or explicit constrained egress placement; existing network-disabled isolation is not removed wholesale.
- [x] Report/output workspace slots and artifact promotion use existing governed contracts; worker-local files are not the only durable output.
- [ ] One sync subagent (in-process) and one async subagent on the RRM-013 Agent Server are qualified inside the production worker composition. Each has explicit capability slices, reservations, dependency/result decisions and cancellation/reconnect behavior. A fake Agent Protocol client does not satisfy this. *(Partly proven: both subagents run inside the production composition with capability slices, reservations and result decisions, live on the RRM-009 Agent Server. Async cancellation and reconnect were re-proven only by the RRM-013 live drills against the scope-claim server, not inside the production worker composition, whose cancel path waits on the RRM-008 merge wiring. Sync-child cancellation was not exercised.)*
- [x] Credential references, exact filters/tool schemas, runtime/placement digests, capability invocation and observed usage appear in sanitized lineage.
- [x] Small technical API-to-Temporal provider/service qualification proves availability and accepted persistence; no Qualia/GenerationLab definitions, searches or report runs.
- [x] Document deployment prerequisites, reproducible launch commands, explicit live opt-in flags and cleanup; replay/recovery regressions pass.
- [x] Search Attributes (REQ-CP-EXEC-015, added by the RRM-005 review): the live composition (`app/application/runners/web_research_coordinator_live.py:704`, today a plain `TemporalWorkflowSubmitter(...)`) and every production root starter use `TemporalWorkflowSubmitter.for_production(..., search_attribute_policy="required")`. The deployment runs `register_belllabs_search_attributes(client, namespace)` (`app/temporal/search_attributes.py`) as its idempotent administrative step and `verify_belllabs_search_attributes(client, namespace)` in worker readiness; readiness never mutates the namespace. A qualification lists the run's root, family and operations by `BellLabsRunId` and `BellLabsUnitKey` on the persistent namespace.
- [x] Inspection composition (REQ-CP-RUN-011/012, added by the RRM-005 review): the server composition attaches, on `app.state` before the first inspection request, `temporal_visibility_reader` (`TemporalVisibilityInspectionReader(client)`), `inspection_checkpoint_reader` (`LangGraphCheckpointHistoryReader({checkpointer digest: the registered persistent saver})`), `inspection_async_child_details` (the Mongo async-child detail repository) and one shared `inspection_cursor_key` (at least 16 bytes, the same on every replica). Without them those sections stay `unavailable` (`app/api/runtime_inspection.py`, `get_runtime_inspection_service`).
- [x] Boundary intervention delivery (RRM-007, added by its review, F6): there is no automatic relay loop and `app.state.boundary_command_transport` is not composed by the server. The deployment must (a) attach `boundary_command_transport = TemporalBoundaryCommandTransport(client)` on `app.state` before the first `/run-control/v1/runs/{run_id}/commands` request so the facade delivers on acceptance, and (b) run a delivery relay (`BoundaryInterventionService.redeliver` / `BoundaryCommandDeliveryService.deliver_pending` per run with pending commands, or delivery at outbox time) so that a command whose inline delivery failed is redelivered in order. Also attach `unit_reconciliation_nudge = TemporalUnitReconciliationNudge(client)` and `unit_reconciliation_verifier` for `/reconcile-unit`. A qualification proves a pause accepted while the transport is down is delivered and applied once the relay runs.

- [x] **Async Agent Server credential (from RRM-013 review N8).** The dedicated async subagent server (`langgraph.async_subagents.json`) authenticates the parent with one static bearer token (`environment:BELLABS_ASYNC_SUBAGENT_SERVER_TOKEN`) and takes the request scope from the `x-belllabs-request-scope` header the client asserts, so scope isolation on that server is client-asserted. Production composition must bind the credential to the scope (a per-scope token or a signed scope claim) or mediate the server behind BellLabs auth, and must keep `LANGSMITH_TRACING` for the hosted children an explicit opt-in.
